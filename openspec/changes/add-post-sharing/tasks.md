# Tasks

The project has no test framework. Each task is verified with `npm run build` plus the check named in it: inspecting the built HTML under `dist/`, or using `npm run dev` / `npm run preview` in a browser with DevTools.

## 1. Canonical site URL

- [x] 1.1 Set `site: "https://tedvu.com"` in `astro.config.mjs`. Verify that `npm run build` passes and that `grep -rl "example.com" dist` returns nothing, which covers the pages, `sitemap-*.xml` and `rss.xml`.

## 2. Preview metadata in the head

Verify in `dist/index.html` and `dist/about/index.html` that every tag appears exactly once, `og:type` is `website`, and `og:image` is `https://tedvu.com/og-default.jpg`.
- [x] 2.3 Add `plainTextExcerpt(document, max = 160)` and `firstImageAsset(document)` to `src/lib/contentful.ts` as in design.md Decisions 5 and 6. Verify with a throwaway `node` check on hand-made rich-text documents, run from the scratchpad and not committed. - [x] 2.4 In `src/pages/blog/[post].astro`, add `description` and `image` (Contentful image URL with `?w=1200&h=630&fit=fill&fm=jpg&q=80`, width 1200, height 630, alt from asset description or title, else the post title) to each post's props. In `BlogPost.astro`, pass `description`, `image`, `type="article"` and the section locale (`vi_VN` for `viet/…`, otherwise `en_US`) to `BaseHead`, and turn a `/viet/` `heroImage` into an absolute image with alt = the title. Then remove the temporary post.

## 3. Share controls

- [x] 3.1 Create `src/components/ShareButtons.astro` as in design.md Decisions 1–3. Include the Facebook, X and WhatsApp `<a>` links (with `target="_blank" rel="noopener noreferrer"`, encoded with `encodeURIComponent`), the Copy link and **Share…** buttons (the latter `hidden` by default), the inline `currentColor` SVG icons, `aria-label`s and `title`s, a visually hidden `aria-live="polite"` region, and token-based pill styles with a visible `:focus-visible` ring. Verify in the built HTML of a post whose title contains `&` or `?` that each link's `href` decodes back to the exact title and `https://tedvu.com/blog/<slug>/`.
- [x] 3.2 Add the bundled script: the delegated `document` click handler for `[data-share-copy]` (clipboard write, "Copied" for 2 seconds plus the live-region announcement, `window.prompt` fallback) and `[data-share-native]` (`navigator.share`, ignoring `AbortError`, falling back to copy), and the `astro:page-load` handler that unhides **Share…** when `"share" in navigator`. Verify that Copy link puts the URL on the clipboard, and that after overriding `navigator.clipboard.writeText` to reject in the console, a prompt shows the URL. In desktop Chrome on Windows (which supports Web Share), **Share…** is visible and opens the share sheet, and closing the sheet logs no console error. In Firefox desktop, **Share…** stays hidden.
- [x] 3.3 In `BlogPost.astro`, wrap each `LikeButton` and a `ShareButtons` in a `.post-actions` row, top and bottom, rendered only when `isPost`, and pass the canonical URL and title. Move `.like.top` and `.like.bottom`'s margins and border into the row styles in `LikeButton.vue`, as in design.md Decision 3. Verify that a post shows both rows, that the top row is centered and the bottom row keeps its separator, and that at 375px and 320px wide the rows wrap without horizontal scroll. Verify the home page, `/blog/`, `/about` and `/top-100` show no share controls, and the like button still works and stays in sync between top and bottom.
- [x] 3.4 Verify accessibility and theming. Tab through both rows: each control gets a visible focus ring in the light and dark themes, Enter activates links, and Enter and Space activate buttons. The DevTools Accessibility pane shows "Share on Facebook", "Share on X", "Share on WhatsApp", "Copy link" and "Share via…". Icon contrast against the pill background is at least 3:1 in both themes, checked with the DevTools contrast picker.
- [x] 3.5 Verify no third-party requests. With DevTools Network open and the cache disabled, load a post on `npm run preview`, and filter for `facebook|x.com|twitter|whatsapp|wa.me|zalo`. There should be no requests until a share link is clicked.
- [x] 3.6 Verify client-side navigation. Open post A, follow an in-site link to post B, then use Copy link, **Share…**, and hover each platform link. All of them use post B's URL and title, and no handler fires twice per click (Copy shows a single "Copied", and the share sheet opens once).
